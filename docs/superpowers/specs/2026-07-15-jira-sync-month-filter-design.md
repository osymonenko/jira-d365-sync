# Design: фильтр по месяцу для Jira-sync

**Дата:** 2026-07-15
**Область:** только Jira → Excel sync (`scripts/jira-sync.py` + `jira-sync.ps1`). `Submit → D365` не затрагивается.

## Проблема

Jira-sync генерит строки задач на неделю; JQL-запросы берут диапазон **всей недели**
(`created >= week_start AND created <= week_end`, либо `DURING (week_start, week_end)`).

Когда пользователь собирает данные за месяц (напр. ИЮЛЬ), первая неделя месяца
частично заходит на предыдущий месяц (напр. неделя 29 июня – 5 июля). За июньские дни
пользователь уже отчитался в июньском прогоне. Текущий sync посчитал бы активность
за все 7 дней недели, включая 29–30 июня → **двойной учёт** уже отчитанной работы.

## Решение (подход 1: обрезка окна JQL)

Пользователь указывает месяц. Недели, пересекающиеся с месяцем, берутся в обработку,
но **окно дат для JQL обрезается** до пределов месяца:
`query_window = [max(week_start, month_first), min(week_end, month_last)]`.

Для пограничной недели 29 июня – 5 июля при месяце «июль» окно становится 1–5 июля.
Июньские дни не запрашиваются повторно; июльские дни этой недели не теряются.

Недели полностью вне месяца отбрасываются.

Будущие дни (месяц ещё не закончился) отсекаются естественно — в Jira нет активности
после «сегодня», отдельная обрезка по текущей дате не нужна.

### Отклонённые альтернативы

- **Пропускать пограничные недели целиком** — теряются реальные июльские дни (1–5 июля).
- **Брать пограничную неделю без обрезки** — ровно тот двойной учёт июня, который убираем.

## Изменения

### `scripts/jira-sync.py`

1. Новый аргумент `--month YYYY-MM` (в `main()` argparse).
2. Валидация формата; при невалидном — ошибка и `sys.exit(1)`.
3. В `cmd_sync`, если `--month` задан:
   - Вычислить `month_first` (1-е число) и `month_last` (последний день месяца).
   - Отфильтровать `weeks_info`: оставить недели, где
     `week_start <= month_last AND week_end >= month_first` (пересечение с месяцем).
   - Для каждой недели вычислить обрезанное окно `q_start = max(week_start, month_first)`,
     `q_end = min(week_end, month_last)` и передать его в `generate_week_rows`.
   - **Ключ вставки строк остаётся `fmt(week["week_start"])`** (реальный старт недели),
     чтобы строки легли в правильный блок недели в Excel. Меняется только окно JQL.
4. Взаимодействие `--month` и `--weeks`: если заданы оба, `--weeks` дополнительно сужает
   уже отфильтрованный по месяцу список (пересечение). На практике GUI при выбранном
   месяце `--weeks` не передаёт.

### `jira-sync.ps1` (GUI)

1. В полосу "Weeks" (`$pnlWeeks`) добавить выпадающий список **"Month:"** (ComboBox).
   - Значения: `All` + месяцы, присутствующие в файле (напр. `June 2026`, `July 2026`).
   - Заполняется при "Read File" из того же JSON недель (`read-weeks`): для каждой недели
     берём месяцы, которые она задевает (start и end), собираем уникальный
     отсортированный список.
   - Значение хранит машинный `YYYY-MM` в `.Tag`/параллельном маппинге; отображает
     человекочитаемое `June 2026`.
   - Дефолт: `All`.
2. При "Sync Jira -> Excel" (`$btnSync`):
   - если выбран конкретный месяц → добавить в аргументы ` --month YYYY-MM`;
     чекбоксы недель на этот прогон **игнорируются** (месяц сам выбирает недели);
   - если `All` → поведение как сейчас (работают чекбоксы недель, передаётся `--weeks`).
3. Панель недель и её высота при выборе месяца не пересчитываются заново — чекбоксы
   остаются видимыми (как индикатор содержимого файла), но не влияют на прогон с месяцем.

## Тестирование

`jira-sync.py` вызывает сеть (Jira API), поэтому фокус на чистых, юнит-тестируемых функциях:

- Вынести логику обрезки в чистую функцию, напр.
  `clamp_week_to_month(week_start, week_end, month) -> (q_start, q_end) | None`
  (возвращает `None`, если неделя не пересекается с месяцем).
- Юнит-тесты (pytest или простой скрипт-ассерт, т.к. в проекте пока нет pytest для python):
  - неделя целиком в месяце → окно без изменений;
  - пограничная неделя начала месяца (29 июня – 5 июля, месяц июль) → 1–5 июля;
  - пограничная неделя конца месяца (27 июля – 2 авг, месяц июль) → 27–31 июля;
  - неделя целиком вне месяца → `None`;
  - неделя, охватывающая весь месяц целиком (маловероятно) → границы месяца.
- Валидация `--month`: невалидная строка → ненулевой exit code.

GUI (`jira-sync.ps1`) вручную: Read File → выбрать месяц в списке → Sync → проверить,
что в лог уходит правильный `--month` и в Excel пограничная неделя не задваивает июнь.

## Не входит в объём

- `Submit → D365` (TS-часть, `src/`) — доделывается позже отдельно.
- Обрезка по текущей дате («месяц не закончился») — не нужна, отсекается естественно.
- Фильтрация уже вставленных строк по дате — sync и так пропускает дубли по имени
  (`existing_names`), логика вставки не меняется.
